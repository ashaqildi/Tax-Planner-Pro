The import created the matched schema and copied a consistent source snapshot in one target transaction. JSON recordset insertion preserved PostgreSQL decimal values and timestamp precision without passing database values through JavaScript Date/Number conversion. Every row was read back and hashed against the snapshot before commit. All primary IDs, sequence last values/is_called flags, primary keys and cascading foreign keys were preserved.

All 52 columns were then compared against the target for type, precision, nullability and physical order. This is a point-in-time transfer; later writes in the original Replit app do not synchronize automatically. Keep using only one app for real updates after cutover, or plan a fresh controlled reconciliation before another cutover.

The first import connection closed before commit. Supabase retained that failed session as an idle transaction, blocking the next attempt. Its session was identified by the exact failed migration SQL and closed; no committed target data was deleted. Import then used batched recordsets and completed successfully. Future migrations should release read-only source snapshots promptly, use bounded statement/lock timeouts, and verify commit state rather than blindly retrying writes.

## Connection configuration and Vercel

Supabase's shared pooler requires its official database CA. certs/supabase-prod-ca-2021.crt was downloaded using the dashboard's SSL Configuration link. The public certificate is bundled as lib/db/supabase-ca.mjs so production function tracing cannot omit it. connection-options.mjs removes URI SSL overrides for Supabase and applies the CA with rejectUnauthorized=true, preserving both certificate and hostname verification. Both session (5432) and transaction (6543) poolers were tested successfully.

The app uses the transaction pooler, three maximum connections per instance, five-second idle timeout, socket keepalive and safe idle-error handling. Vercel Fluid Compute's attachDatabasePool manages pool suspension. No automatic business-write retries were added. vercel.json selects iad1 to match the database region. Keep the target on the same Supabase project and copy server-only DATABASE_URL from local configuration into Vercel Production environment settings; use a separate test database for Preview. Restart/redeploy after changing credentials or environment variables. Never expose URLs through NEXT_PUBLIC_ variables.

No Vercel deployment has yet been run or remotely verified. The local .env.local is not uploaded or automatically copied into Vercel. Free Supabase projects may pause for inactivity and are quota-limited; pooling cannot prevent provider pauses or guarantee uninterrupted availability. Connection credentials shared in chat should be rotated before public deployment, then updated locally and in Vercel together.
